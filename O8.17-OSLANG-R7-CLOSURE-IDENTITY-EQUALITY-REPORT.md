# O8.17-OSLANG-R7-CLOSURE-IDENTITY-EQUALITY-REPORT.md

## Equality contract confirmed

Per the architectural decision, equality is identity-based for runtime
reference values:

- Array equality: identity-based (unchanged).
- Object equality: identity-based (unchanged).
- Closure equality: identity-based (R7).
- The same reference compares equal to itself.
- Distinct references compare unequal, even when contents appear equivalent.
- Equality does not invoke closure execution or compare function bodies/
  captured values structurally.

## Closure representation and identity mechanism

`Value` is a `readonly partial struct` tagged union (`engine/Core/Values/Value.cs`).
A closure reference is stored in the `_heapRef` object field under `ValueKind.Closure`:

- `Value.Closure(HeapClosure)` constructs a closure value.
- `Value.AsClosure` returns `(HeapClosure)_heapRef` for `ValueKind.Closure`,
  `null!` otherwise.
- `HeapClosure` (`engine/Core/Values/HeapObjects.cs:231`) is `public sealed
  class HeapClosure : HeapObject` with fields `Function` and `Value[] Captured`.
- `HeapClosure` declares no `operator ==` and no `Equals` override, and its
  base `HeapObject` declares none either. Therefore `HeapClosure == HeapClosure`
  resolves to `object.operator==`, i.e. reference identity — exactly matching
  the existing `a.AsArray == b.AsArray` / `a.AsObject == b.AsObject` pattern.

`ValuesEqual` (`engine/Core/Eval/ValueUtilities.cs`) already kind-checks first
(`a.Kind != b.Kind => false`), so the Closure arm only runs when both operands
are `ValueKind.Closure`, guaranteeing non-null heap refs for well-formed
closure values. Null / invalid-value / cross-kind behavior is unchanged.

## Exact implementation details

```csharp
ValueKind.Closure => a.AsClosure == b.AsClosure,
```

Placed between the Array and Object arms, preserving the existing reference
identity pattern. No structural comparison, no closure invocation.

language syntax, and `RELIABILITY-AUDIT-BACKLOG.md` R4 limitation were not

## Regression tests and results

`host/CollectionTests/ClosureEqualityTests.cs` — 18 tests, all exercising
`ValueUtilities.ValuesEqual` (the language-level equality path; `ExpressionEvaluator.EvaluateBinary`
`=`/`<>` calls `ValuesEqual` directly), plus one end-to-end interpreter test:

1. `Closure.SelfEqualityIsTrue` — closure vs itself => true.
2. `Closure.DistinctSameBodyNotEqual` — distinct closures, same body => false.
3. `Closure.DistinctEquivalentCapturesNotEqual` — distinct closures, equivalent
   captures => false.
4. `Closure.DistinctDifferentCapturesNotEqual` — distinct closures, different
   captures => false.
5. `Closure.VersusNumberIsFalse` / `Closure.VersusNullIsFalse` /
   `Closure.VersusStringIsFalse` — cross-kind / null => false.
6. `Closure.EqualsDoesNotExecuteBody` — interpreter run: `MAIN` assigns a
   closure of `FOO` (whose body divides by zero) to `c`, returns `c = c`;
   result `true`, flow `Normal` — body never executed.
7. `Array.DistinctSameContentNotEqual` / `Array.SameReferenceEqual` — array
   identity unchanged.
8. `Object.DistinctSameContentNotEqual` / `Object.SameReferenceEqual` — object
   identity unchanged.
9. `Primitive.NumberEqual/NotEqual`, `Primitive.StringEqual/NotEqual`,
   `Primitive.BooleanEqual`, `Primitive.NullEqual` — primitive equality
   unchanged.

Suite result: **772 passed, 0 failed** (754 pre-existing + 18 new R7 tests).

  path (pre-existing R2 limitation).
