## Executive Summary
This milestone addressed **R8 — Runtime Error Model Consistency** from the OSLANG Reliability Audit Backlog. Two code paths were found to throw raw C# exceptions (`InvalidOperationException`) that bypassed the interpreter's `ControlFlow.Exception` soft-throw system, preventing `TRY/CATCH` from catching these user-facing runtime errors. Both defects have been fixed with minimal, targeted changes, and regression tests added. All 871 CollectionTests pass.

## Confirmed Defects

### Defect 1: `StandardLibrary.Count` bypasses soft-throw
- **File:** `engine/Core/Eval/StandardLibrary.cs:107`
- **Before:** `throw new InvalidOperationException($"COUNT not supported for {value.Kind}")`
- **Impact:** `COUNT(5)`, `COUNT(true)`, `COUNT({})` crashed with unhandled C# exception; `TRY/CATCH` ineffective
- **Fix:** Added `ExecutionContext` and `SourceLocation` parameters; replaced with `ctx.Throw($"COUNT not supported for {value.Kind}", location)`

### Defect 2: `ValueUtilities.ToDisplayString` throws for arrays
- **File:** `engine/Core/Eval/ValueUtilities.cs:47`
- **Before:** `ValueKind.Array => throw new InvalidOperationException("Cannot convert ARRAY to STRING")`
- **Impact:** `PRINT [1,2]` crashed with unhandled C# exception
- **Fix:** Changed to `ValueKind.Array => $"ARRAY[{value.AsArray.Length}]"` (consistent with `Value.ToString()`)

## Remaining Limitations & Unresolved Semantic Decisions

1. **`AsX` properties on `Value`** still return `NaN`/`null!` on kind mismatch (R4 limitation). Only `TryAsX` accessors provide explicit failure. Engine call sites guard kind first, so this is not a runtime defect.

2. **`StringMap` internal exceptions** remain as C# exceptions. If `StringMap.Remove` is ever used in a user-facing context, a wrapper may be needed. Currently unused in engine.

3. **`FrameStack` empty-stack exceptions** are intentional programmer-bug signals (R6 fix). Not user-catchable.

4. **`EngineHeap` OOM** throws `OutOfMemoryException` directly (R2 fix). Not recoverable via language `TRY/CATCH`.

5. **R9 host-level error surfacing** deferred to Batch 8 pending O8.15 separation.
