# O3.5.3 Hybrid Runtime Architecture — Implementation Plan

## Overview

This plan addresses the NativeAOT compatibility blockers discovered in O3.5.3 using the approved Hybrid approach:
1. **Refactor Parser/Lexer** to use freestanding collections instead of BCL `List<T>`, `Dictionary<K,V>`, `HashSet<T>`
2. **Extend MiniCoreLib** with only essential compiler/runtime support types
3. **Convert record types** in AstNodes to `readonly struct` to eliminate `IsExternalInit` dependency
4. **Preserve Hosted execution path** compatibility throughout

### 2.5 Parser Refactoring Details

All `new List<T>()` → `new NodeList<T>()` with same initial capacity (default 4).
All `.Add()` calls unchanged.
All returned lists passed to AST node constructors — **AST node constructors must change** from `IReadOnlyList<T>` to `NodeList<T>` or accept both.

**Strategy**: Change AST node collection properties from `IReadOnlyList<T>` to `NodeList<T>` (implements `IReadOnlyList<T>`). This preserves Hosted compatibility if Hosted code uses the interface.

#### 4.1.6 StringComparer (Priority 1)

```csharp
namespace System
{
    public abstract class StringComparer : IEqualityComparer<string>, IEqualityComparer
    {
        public static StringComparer OrdinalIgnoreCase { get; } = new OrdinalIgnoreCaseComparer();
        
        public abstract bool Equals(string x, string y);
        public abstract int GetHashCode(string obj);
        bool IEqualityComparer.Equals(object x, object y) => Equals((string)x, (string)y);
        int IEqualityComparer.GetHashCode(object obj) => GetHashCode((string)obj);

        private sealed class OrdinalIgnoreCaseComparer : StringComparer
        {
            public override bool Equals(string x, string y) 
                => string.Compare(x, y, StringComparison.OrdinalIgnoreCase) == 0;
            public override int GetHashCode(string obj)
            {
                // Simple case-insensitive hash
                int h = 0;
                foreach (char c in obj)
                    h = h * 31 + char.ToUpperInvariant(c);
                return h;
            }
        }
    }
}
```

## Phase 6 — Memory and Runtime Risks

### 6.1 EngineHeap Integration

| Risk | Mitigation |
|------|------------|
| `NodeList<T>` uses managed `T[]` arrays | EngineHeap already tracks managed objects via GCHandle — no change |
| `NodeList<T>` growth triggers allocation | Same as ValueArray — uses `Array.Copy`, no new patterns |
| GCHandle overhead for NodeList | NodeList not heap-tracked directly; only AST nodes are |

### 6.2 GC Root Handling

- `ExecutionContext.Frames` → `FrameStack` (freestanding, no GC)
- `ExecutionContext.Globals` → `ValueArray` (freestanding, no GC)
- `Frame.Locals` → `StringMap<Value>` (freestanding, no GC)
- AST nodes during parsing: temporary `NodeList<T>` on managed heap, short-lived, collected normally

### 6.3 Collection Growth

- `NodeList<T>`: doubles capacity (same as ValueArray)
- `StringMap<T>`: doubles at 0.75 load factor (unchanged)
- `StringBuffer`: doubles capacity (unchanged)
- Max AST size bounded by source size → no unbounded growth

### 6.4 Allocation Ownership

- Parser/Lexer: temporary managed allocations during parse
- AST nodes: managed objects, rooted by ExecutionContext during execution
- Freestanding collections: manage their own internal arrays

### 6.5 Static Initialization

- `Keywords.Map` → `StringMap<TokenType>` static readonly
- `Parser.BuiltinCallKeywords` → `TokenTypeSet` static readonly
- No circular dependencies

### 6.6 Type Metadata

- `readonly struct` AST nodes: no additional metadata vs records
- `NodeList<T>`: generic type, instantiated per T used in Parser
- Generic instantiation count: ~15 (FunctionDecl, ClassDecl, Stmt, Expr, etc.)

### 6.7 Exception Behavior

- Parser throws `SyntaxException` (custom, not BCL)
- EngineHeap throws `OutOfMemoryException` (MiniCoreLib addition)
- StringMap throws `ArgumentNullException`, `KeyNotFoundException` (MiniCoreLib additions)
- All catch sites already handle `Exception` base

### 6.8 OOM Behavior

- EngineHeap `ThrowOOM()` throws `OutOfMemoryException`
- `NodeList<T>` growth calls `Array.Copy` — if OOM, CLR throws
- No custom OOM handling needed in collections
