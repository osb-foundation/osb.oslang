# O8.20-OSLANG-BATCH-8-R9-HOST-ERROR-SURFACING-REPORT.md

## Objective and R9 Definition

**R9 — Host-level Error Surfacing**: The host (OSLANG.EXE entry point in `OsbMain.cs`) must not report successful execution when the OSLANG interpreter terminates with a runtime error. Previously, `interpreter.Execute(program)` was called but `interpreter.CurrentFlow` was never checked, causing runtime failures (division by zero, missing MAIN, unknown function, etc.) to exit silently with code 0 and no diagnostic.

- **Final Commit**: `330ec69` — "O8.20 Batch 8: R9 Host-level Error Surfacing"

## Reproduction of the Original Defect

**Code inspection** of `OsbMain.cs` (lines 339-340) showed:
```csharp
var interpreter = new Osb.Engine.Core.Eval.Interpreter(heap, host, math, time, random, utf8);
interpreter.Execute(program);
```

No check of `interpreter.CurrentFlow` after `Execute()` returned. The interpreter uses a soft-throw model (`ControlFlow.Exception`) that does not throw C# exceptions. The existing `catch (Exception ex)` block only catches C# exceptions, not the soft-throw path.

**Evidence from RELIABILITY-AUDIT-BACKLOG.md**: "Process exits 0 with no diagnostic" for runtime failures.

## Root Cause

The host entry point (`OsbMain.Main()`) did not observe the interpreter's error state after execution. The interpreter correctly sets `CurrentFlow = ControlFlow.Exception` and populates `CurrentExceptionMessage` for runtime errors (via R1 public getters), but the host never checked these properties.

## Exact Implementation Changes

### 1. `engine/host/Host.Osb/OsbMain.cs` (lines 341-347 added)

After `interpreter.Execute(program)`, added:
```csharp
if (interpreter.CurrentFlow == Osb.Engine.Core.Eval.ControlFlow.Exception)
{
    Syscall.PrintString("Runtime error: ");
    Syscall.PrintString(interpreter.CurrentExceptionMessage ?? "unknown");
    Syscall.PrintString("\r\n");
    Syscall.Exit(1);
}
```

This mirrors the existing C# exception catch block but handles the soft-throw `ControlFlow.Exception` path.

Fixed a pre-existing compile-breaking typo in the O8.15 probe block:
- **Before**: `int l = "USING".L6666666666666ength;`

All O8.15 probe markers (`KW_PRE`, `ARR_OK`, `TARR_OK`, `BARR_OK`, `SC_OK`, `LEN_OK`, `IDX_OK`, `EQ_OK`, `KW1_OK`/`KW1_NO`, `KW2_OK`/`KW2_NO`, `KW_POST`, `B4LEX$`, `AFLEX$`, `AFLEX2`, `NL_PRE`, `NL_POST`, `IAE_PRE`, `IAE_POST`, `M_PRE`, `M_POST`, `M_ADD`, `IAE_POST2`, `M_EOF`, `LEX$`, `PAR$`) and logic are **preserved**.
