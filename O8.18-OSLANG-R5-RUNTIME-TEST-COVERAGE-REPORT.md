# OSB / OSLANG — Batch 6 (R5) Runtime Test Coverage Report

## Executive summary

Batch 6 (R5 — Runtime Test Coverage) strengthened the automated test coverage of the `osb.Engine.Core` runtime, identified an uncovered critical behavioral contract, reproduced it, and implemented a minimal correction. The audit confirmed that `host/CollectionTests` covered lexer/parser/collections but had no interpreter-level behavioral coverage for function/method invocation, expression evaluation, flow control, object/array mutation, or exception propagation across execution boundaries.

One confirmed R5 defect was found and fixed: `ExpressionEvaluator.EvaluateNew` did not check `_ctx.CurrentFlow` after evaluating constructor arguments, and `Interpreter.CallMethod` unconditionally reset flow to `Normal` at entry. `NEW Foo(1 / 0)` therefore swallowed the division-by-zero exception and returned an object with `Normal` flow. Fixed by checking flow after each argument evaluation in `EvaluateNew`, matching the existing `EvaluateCall`/`EvaluateMethodCall` pattern. Regression coverage was added.

All Batch 6 work is committed. O8.15 pre-existing changes (`OsbMain.cs`, `OSLANG.EXE`) remain untouched and uncommitted.

## Defects discovered and fixes implemented

One confirmed R5 defect:

**Exception swallowed by `NEW` / constructor argument evaluation.**

- Root cause: `ExpressionEvaluator.EvaluateNew` evaluated constructor arguments without checking `_ctx.CurrentFlow` after each argument, and `Interpreter.CallMethod` unconditionally set `CurrentFlow = Normal` at frame entry. `NEW Foo(1 / 0)` raised "Division by zero." (flow `Exception`), then `CallMethod` clobbered it to `Normal`, ran the constructor, and returned an object with `Normal` flow — the exception was silently lost at a constructor boundary (an R1-class exception-flow regression in the `NEW` path).
- Fix (`engine/Core/Eval/ExpressionEvaluator.cs`, `EvaluateNew`): check `if (_ctx.CurrentFlow != ControlFlow.Normal) return Value.NullValue;` after each argument evaluation, matching `EvaluateCall`/`EvaluateMethodCall`. On a throwing argument, `NullValue` is returned with `Exception` flow preserved; no object is allocated and no constructor runs.
- Regression test: `Runtime.NewWithArgThatThrowsPreservesException` asserts flow `Exception` and message "Division by zero." — failed before the fix (`flow=Normal`), passes after.
- No architecture, value-system, closure, object-identity, allocation, execution-model, or language-semantics changes.

No other defects were confirmed. No speculative fixes were made. R8/R9 defects were deliberately left for their dedicated milestones.
