# OSLANG Owner Decisions

**Status:** SQ-001, SQ-002, SQ-003 are **OFFICIALLY APPROVED** (2026-11-19). Remaining items pending.

| ID | Question | Recommended Decision | Technical Rationale | Clarification Needed | Impact | Deadline | Status |
|---|---|---|---|---|---|---|---|
| SQ-001 | String indexing unit (UTF-8 bytes / code points / UTF-16 code units) | **Unicode code points (OFFICIAL)** | Spec says "Unicode text" (§3); code points align with `SUBSTR`/`INDEXOF` semantics. **Code points ≠ grapheme clusters** — combining sequences (e.g., "e\u0301") are 2 code points, 1 grapheme. Engine stores UTF-8 bytes; code-point indexing requires decode on every operation. Host (BCL) uses UTF-16; transcoding on entry needed. | **OFFICIALLY DECIDED: CODEPOINT** — `s[0]` returns STRING with one Unicode code point. Invalid UTF-8 follows existing runtime string validation policy. | O3b (Values/Strings), array/string interop, `LEFT`/`RIGHT`/`PAD*` | O3b start | **APPROVED** |
| SQ-002 | Case-folding rule (ASCII-only / full Unicode) | **ASCII-only (OFFICIAL)** | OS is DOS-like; identifiers/keywords/enums are ASCII in practice. Full Unicode adds ICU-scale tables and locale dependency. Spec says "case-insensitive everywhere" but no algorithm. Algorithm: for each character `c`, if `'A'` ≤ `c` ≤ `'Z'` then `c + 0x20` else `c` unchanged. Non-ASCII preserved unchanged. | **OFFICIALLY DECIDED: ASCII-ONLY** — `TOUPPER`/`TOLOWER` convert only ASCII A-Z/a-z. Non-ASCII unchanged. No locale-dependent behavior. | Lexer, identifier resolution, enum member names, property lookup | O3a (lexer) | **APPROVED** |
| SQ-003 | EVENT/ON/RAISE required for 0.73? | **Defer to post-0.73 (OFFICIAL)** | Spec 0.3 introduced them; 0.73 §16 says "never revisited; no version states whether they are required for 0.73". Both reference and kernel port treat as dead code. Implementing adds complexity without conformance value. | **OFFICIALLY DECIDED: DEFER** — Not part of 0.73 scope. Do not implement partial/experimental versions. Document deferred status consistently. | O3d (OOP/events) | O3d start | **APPROVED** |
| SQ-004 | SWITCH expression syntax/semantics | **Adopt `CASE val => expr` arms; no-match → runtime error** | Spec 0.3: "`SWITCH` is also available as an expression: `CASE1 => "Monday"`". No `DEFAULT` required; expression form must yield a value. Treat missing match as runtime error catchable by `CATCH`. | **OWNER CLARIFICATION REQUIRED** — (1) Syntax: `CASE val => expr` vs `CASE val: => expr`. (2) Typing rule: all arms must share a common type? (unresolved). | O3e (switch), parser, evaluator | O3e start | PENDING |
| SQ-005 | FOR IN collection domain | **Arrays only for 0.73; strings as `ARRAY<STRING>` (chars) later** | Spec: "over any collection". Only arrays exist as collections in 0.73. Strings are primitive `STRING` type, not `ARRAY<STRING>`. `IEnumerable`-shaped types don't exist in OSLANG. | **READY FOR OWNER APPROVAL** | O3e (FOR IN/EACH) | O3e start | PENDING |
| SQ-006 | Error message text and codes | **Engine chooses; conformance tests assert only category + source location** | Spec pins four categories (lexical, syntax, semantic, runtime) but no message texts, numeric codes, or source-location format. Conformance `.out` files must not depend on exact wording. | **ARCHITECTURAL VERIFICATION REQUIRED** — ENGINE-DESIGN §6 proposes "numeric OSLANG error code + message + source location". Spec says `ERR` carries "the message" (string). What does `ERR` bind to — string or error object? What source location format for tests? | O3e (exceptions); test corpus design | O2 (corpus) | PENDING |
| SQ-007 | DATE.FORMAT/TIME.FORMAT extra tokens | **Reject unknown tokens with defined error** | Spec requires `YYYY/MM/DD` and `HH/mm/ss` only. `MONTHNAME`/`DAYNAME` mention "runtime locale" but OSB has no locale system. **SPEC-QUESTIONS SQ-018 cross-ref is wrong** — SQ-018 is FOR loop, not locale. | **OWNER CLARIFICATION REQUIRED** — Unknown tokens: reject / ignore / implement common subset? Locale for MONTHNAME/DAYNAME: fixed English / configurable / stub? Fix cross-reference. | O4 (DATE/TIME), locale question (separate from SQ-018) | O4 start | PENDING |
| SQ-008 | TYPEOF exact strings | **Uppercase for primitives (`NUMBER`, `STRING`, `BOOLEAN`, `ARRAY`, `NULL`), class name as declared, enum name as declared, `KEYEVENT` for key events, `SIZE`/`CURSOR` for those structs, `ENUMSET` for enum sets** | Spec: "runtime type name". Consistency with keyword casing (uppercase). Key event type name not specified — `KEYCODE` is the enum of `KEY` property, not event type. `SIZE`/`CURSOR` from `OSL.CONSOLE.SIZE()`/`GETCURSOR()`. **`KEYEVENT`, `SIZE`, `CURSOR`, `ENUMSET` are proposed names, not normative requirements.** | **OWNER CLARIFICATION REQUIRED** — Confirm `KEYEVENT` (not `KEYCODE`), `SIZE`/`CURSOR` distinct from `ARRAY`/`OBJECT`, case for closures/module values. | O3c/O3e | O3c start | PENDING |
| SQ-009 | Array mutation: SORT/REVERSE/PUSH/POP | **`SORT` non-mutating (returns new array); `REVERSE` — owner decision required; `PUSH`/`POP`/`ADD`/`REMOVE`/`CLEAR` mutate in place** | Spec §12 says `SORT` does not mutate; "Mutation" paragraph lists `REVERSE` as mutating ("mutating methods... change the array they are called on"). `PUSH` as statement must mutate. Host returns new array from `SORT`; kernel mutates. **SORT contradiction documented; REVERSE not explicitly specified as non-mutating.** | **OWNER CLARIFICATION REQUIRED** — `REVERSE`: mutating (per Mutation paragraph) or non-mutating (functional style, useless as statement)? | O3c (arrays), O4 `.out` expectations | O3c start | PENDING |
| SQ-010 | EOF behavior of file streams | **`READLINE()` at EOF → `NULL`; `READ()` at EOF → 0 bytes; `EOF()` true after failed read** | Spec silent. `NULL` distinct from empty string; `READ` returning 0 matches POSIX-like semantics. `EOF()` becomes true after a read that returns 0/`NULL`. | **DEFERRED** — Spec completely silent; reasonable behavior can be chosen during O4 based on kernel syscall behavior. Not a 0.73 conformance blocker. | O4 (`OSL.FILE`), K3 read past end | K3 design | PENDING |
| SQ-011 | Path case-sensitivity | **Kernel normalizes to case-insensitive DOS resolution; engine passes paths through unmodified** | OSB-ARCHITECTURE §9: "case-insensitive path resolution in the DOS layer while preserving on-disk names". | SQ-012 | EXIT(code) range | **0–255 (byte), truncated modulo 256** | Spec: "ends the program". D4: "script exit code = process exit code". Kernel `EXIT` (4Ch) takes `AL` (byte). | SQ-013 | Number precision/formatting | **IEEE-754 double; fixed-precision fractional output (e.g. 12 digits), exponent for large magnitudes; `ROUND` = banker's rounding (ties to even)** | Spec: "floating point where the host needs it". Three separate concerns: (1) Representation: IEEE-754 double (only portable choice). (2) Output formatting: spec doesn't specify digit count; kernel port uses 12 (defect per GAP). (3) `ROUND` mode: banker's rounding is standard for financial but not universal (BASICs often use round-half-up). | **OWNER CLARIFICATION REQUIRED** — Owner must decide: exact output formatting algorithm (shortest round-trip like JS/Java? fixed N digits?). `ROUND` mode: banker's (ties to even) or round-half-up? `ROUND(V, Digits)` with negative digits? | O3b (own double math/formatting) | O3b start | PENDING |
| SQ-014 | KEYCODE numeric values / serial mapping | **Runtime fixes numeric values; deterministic PS/2 + serial ESC[/ESC O → KEYCODE table** | Spec: "exact numeric values are implementation-defined unless explicitly specified by the runtime". Kernel K2 must decode scancodes/serial sequences; engine must not depend on numeric values (use enum members). Fixing values enables deterministic serial mapping. | **READY FOR OWNER APPROVAL** | K2 terminal API, O5 (`OSL.CONSOLE` key events) | K2 design | PENDING |

(3) `USING foo` in MAIN relative to base directory vs imported file relative to importer's directory. | O3e (multi-file/modules), O4 host libraries | O3e start | PENDING |
| SQ-016 | OSB.NET runtime error identity | **Single error code/message: "Network not supported on this host" at call time, catchable by `CATCH`** | Spec lists `OSB.NET.PING`/`DOWN` as host extension; plan requires surface exists and fails with defined error. Same error for both; raised at call time (not only in `TRY`). | **ARCHITECTURAL VERIFICATION REQUIRED** — ENGINE-DESIGN §6 says "SQ-017 assigns its code/message" but SQ-017 is INPUT EOF, not OSB.NET. | SQ-017 | INPUT with no data available | **`INPUT` at EOF → runtime error catchable by `CATCH`** | Spec: "reads a line, always returns STRING". No rule for EOF. | SQ-018 | FOR loop variable visibility / negative STEP | **Loop variable survives after `END` with last value; `STEP` negative allowed (5 TO 1 STEP -1 runs)** | Spec: bounds inclusive, no rule for survival or negative step.
